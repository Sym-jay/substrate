## Live VM isolation and snapshots

The acceptance script created two small 8 GiB guests and one running-state fork.
All three were deleted afterward. The two preexisting VMs remain stopped.

- Open guest cold boot: **2,296 ms**. Allowlisted guest: **2,302 ms**.
- Real x86 Firecracker processes have distinct jail uids, chroots and network
  namespaces. Their roots contain only jail files, excluding host account/data
  directories. The fork has a separate identity and namespace too.
- The open guest reaches public HTTPS. The allowlisted guest picks up the proxy
  through metadata, cannot reach public internet directly, reaches its allowed
  domain through the proxy, and gets a refusal for other domains and EC2 metadata.
- Guests cannot connect to each other or the host's SSH service.
- Durable ZFS/memory pause: **2,969 ms**. Resume: **343 ms**. The same shell PID,
  shell variable, disk marker and scrollback survived restoration.
- A jailed running-state fork retained shell memory and scrollback. A child-only
  write did not appear in the source guest.

The checker never replaced the host firewall or restarted hostd. Existing
workspaces were not booted, paused, changed or deleted.
