## What changed

- The workspace UI adds disk capacity, a GitHub start mode, agent permission
  selection, delete, offline resize, running-state forks, disk rollback points,
  previews, and SSH connection setup.
- Fork saves a full memory/disk checkpoint and makes independent ZFS copies.
  It restores both copies if the original was running. The new VM keeps shell
  variables, processes, terminal IDs and scrollback, but gets a new guest token,
  IP, hostname and SSH host keys. In-flight network connections are not migrated.
  The kernel build requires VMGENID so restores reseed the guest RNG; see
  [Firecracker's clone randomness guidance](https://github.com/firecracker-microvm/firecracker/blob/v1.17.0/docs/snapshotting/random-for-clones.md).
  Full copies can take minutes and use additional pool space. VM creation and
  forks return background jobs and the UI polls them, avoiding CloudFront
  timeouts during large repository clones or VM copies.
- Fork ownership is reserved before the copy starts. Concurrent creates/forks
  cannot exceed the user's quota. If control restarts during a fork, its job
  reports an interruption; refresh the list before retrying. A completed child
  remains visible to its owner.
- CPU/memory changes and disk growth require a stopped VM. Resume a paused VM,
  then stop it first. Shrinking is refused. A disk checkpoint precedes resize.
- Starting an agent through the UI/API takes a synced ZFS disk checkpoint before
  creating the terminal. Ask is the default; full auto selects the installed CLI's
  unattended permission flag. This does not supply an agent subscription/API key.
  Starting a CLI manually inside a shell does not create a checkpoint automatically.
- Rollback requires a stopped VM. It removes later disk changes and later ZFS
  snapshots, then the workspace starts fresh. Run checkpoints are disk-only;
  M3 pause/resume continues to preserve RAM as well.
- Existing images remain bootable. Running-state forks and SSH require a newly
  built M6 guest image; an old VM receives an actionable fork error.

## Preview URL

The existing control distribution stays in place. A second CloudFront
distribution forwards previews to the same control service with an origin
header. It exposes only `/p/<vm-id>/<port>/...`, never control routes.
`PreviewUrl` is a stack output; `/substrate/preview-origin` configures control.

A signed-in owner requests a one-use, 60-second bootstrap link in the workspace
UI. Visiting it sets a Secure, HttpOnly, path-scoped preview cookie and removes
the ticket from the URL. The cookie lasts one hour; open a new link from the UI
after expiry. Ownership is checked on every request. A copied bootstrap link
works once, so treat it as a credential until redeemed. These are private preview
links, not anonymous permanent sharing URLs.

Requests, including development WebSockets and binary frames, pass through
control → hostd → the selected VM. hostd starts/resumes that VM before forwarding.
Ports 1024–65535 are supported except guestd's reserved port 7000. No public VM
port or inbound SSH port is opened.

Apps must bind to `0.0.0.0` and support the preview's **base path**. The UI shows
the exact path. For Vite, for example:

```sh
npm run dev -- --host 0.0.0.0 --base /p/VM_ID/3000/
```

Configure the dev server's host allowlist for the preview hostname if it requires
one. The proxy preserves that base path and query string; it does not rewrite
JavaScript or HTML. Apps that assume the root path need base-path configuration.
Previews have an origin separate from control, so app code cannot read control
cookies. All Phase 1 previews share the preview origin; per-app browser isolation
needs a wildcard/custom-domain scheme later.

## GitHub credentials

Create a fine-grained PAT restricted to selected repositories with Contents and
Pull requests read/write permissions (Metadata read is implicit). Choose an
expiry and grant organization approval when required. Store it against the
owner's **Clerk user ID**, not GitHub username:

```sh
bun run github:token USER_ID
```

The script prompts with input hidden and stores a SecureString at
`/substrate/github/USER_ID`. Never put a token in a command argument, URL, chat, or
source file. Each signed-in user gets only their own credential; a browser cannot
select another user's token. Without a stored token, public repository cloning
still works.

Choose **From GitHub** and enter `owner/repository` or its GitHub HTTPS URL.
guestd writes a dev-owned, mode-0600 credential file and installs a `gh` wrapper
that loads it as `GH_TOKEN`, following the [GitHub CLI guidance for fine-grained
tokens](https://cli.github.com/manual/gh_auth_login). Git's credential helper uses
that wrapper. Git uses the account's GitHub name and noreply commit email.
The repo clones into `/home/dev/workspace`; new sessions start
there. The PAT stays on that VM's private disk so agents and `gh pr create` can use it. Forks and
disk checkpoints copy those credentials too; revoke the PAT to revoke all copies.
The token is not returned to the browser or written to VM metadata/host manifests.
Clone failures leave the created VM visible with an error instead of leaking it.

Inside the terminal, normal Git/gh commands work:

```sh
git switch -c my-change
git add .
git commit -m 'Describe the change'
git push -u origin my-change
gh pr create
```

## SSH and VS Code

Open **SSH and VS Code**, paste a public key from your device, and download the
connection JSON. Keep it private: it authorizes opening this VM's SSH transport
for one hour. The SSH private key remains on your device and is still required
for login. Active SSH sessions can continue after the connection grant expires.

Use Bun 1.4.4+ and this checkout's proxy script:

```sh
ssh -o 'ProxyCommand=bun /absolute/path/substrate/scripts/ssh-proxy.ts /absolute/path/VM_ID-ssh.json' dev@VM_ID
```

For VS Code Remote SSH, add an entry to your local `~/.ssh/config` (replace paths
and VM ID):

```sshconfig
Host substrate-VM_ID
  HostName VM_ID
  User dev
  IdentityFile ~/.ssh/id_ed25519
  ProxyCommand bun /absolute/path/substrate/scripts/ssh-proxy.ts /absolute/path/VM_ID-ssh.json
```

Select that host in VS Code's Remote SSH extension. Download a new connection
file when it expires. Opening SSH resumes a paused VM. SSH allows public keys
only; password and root login are disabled.

## Deploy and verify

Local checks: `bun run typecheck`, `bun test`, the web production build, and CDK
synthesis. `cdk diff --no-change-set` adds only the preview distribution, its SSM
URL parameter and a stack output; neither EC2 instance is replaced. Existing CDK
AMI portability warnings and the web bundle-size warning remain.

The plan requires the user to run the infrastructure deployment. From this
branch/worktree with AWS credentials and Bun 1.4.4:

```sh
cd /private/tmp/substrate-m6/infra
bunx cdk deploy
```

After coordinating the shared deployment, deploy hostd, rebuild the guest image, and
deploy control/web from the same combined source revision:

```sh
bun run deploy:host
bun run images:build
bun run deploy:control
bun run check:m6
```

`check:m6` creates its own two small workspaces and cleans them up. It checks
public repository cloning, forked shell memory/PID/disk/scrollback, independent
parent deletion, checkpoint-before-agent launch, rollback, offline resize, and a
preview waking a paused VM. It does not restart the shared host or hostd. The
test starts Codex without sending a paid task. Ensure there is enough free RAM
and disk for both VMs and their full snapshots before running it.

Finish the user-facing acceptance after deployment:

1. Sign in, create a GitHub workspace, push a disposable branch to a selected
   repo, and open a PR. Confirm a second account cannot access its management,
   preview-link issuance, SSH grants, or fork jobs.
2. Start a base-path-configured dev server, open its preview through the second
   CloudFront URL, and verify assets and hot reload. Pause the VM and reload the
   preview; the running app should return. Expired bootstrap links should fail.
3. Add a public key, connect using SSH and VS Code, and confirm terminal commands
   run as `dev`. Repeat after pausing the VM.
4. Exercise both agent permission modes with your own agent authentication.
   Make a file change, stop, roll back, start, and verify it disappeared.

M6 is not complete until these AWS checks pass. M5 automatic host shutdown stays
deferred for the hackathon.
